我建议你正式采用这套分层：
1. 外层 CLI
- Commander
- 负责子命令、参数、入口调度
2. 轻交互层
- Clack
- 负责 init/login/config/confirm/select
3. 主工作区 TUI
- 不再用 Ink
- 改成自定义：
    - ANSI renderer
    - raw stdin key/mouse parser
    - screen buffer / viewport model
    - status bar / sidebar / editor / message viewport
4. Shell/工具运行
- node-pty
- 只负责 shell / tool / interactive subprocess
- 不负责 UI 渲染
5. 数据与边界
- Zod
- 所有 provider / plugin / config / event 输入都校验
  为什么要这么改
  因为 OpenCode/OpenClaw 之所以顺，不是因为“某个 React 组件写得更好”，而是因为：
- 输入框是输入框
- 聊天 viewport 是 viewport
- 滚动条是滚动条
- 鼠标/键盘/复制是独立控制器
- 渲染是单一终端表面，不是 React/Ink 在帮你猜终端该怎么刷
  而你现在遇到的这些问题：
- 拖滚动条不跟手
- 复制命中偏移
- 输入区和消息区互相影响
- 鼠标行为和终端选择打架
  本质上都是“主 UI 内核选错了”。
  所以现在最正确的策略是：
- 保留已经做对的底层平台化部分：
    - protocol
    - permissions
    - plugin-sdk
    - core-runtime
    - storage-sqlite
    - agent-provider
- 停止继续在现有 Ink TUI 上补交互
- 直接重写主工作区 UI
  推荐迁移顺序
1. 先冻结旧 packages/cli/src/tui 的复杂交互修补
2. 新开一个终端内核目录，比如：
   packages/cli/src/terminal-core/
3. 先做最小版本：
- message viewport
- input editor
- status bar
- sidebar
- streaming render
4. 再接：
- scrollbar
- copy/select
- tool panel
- diff panel
- shell panel
5. 最后替换旧 TUI 入口
   一句话结论
   是的，UI 应该按你贴的这套做。  
   而且更准确地说：
- Commander + Clack 做外层
- 自定义 ANSI/raw-stdin/node-pty 做主工作区
- Ink 不要再做主渲染核心
